# ماژول خدمات نسخه ۳ — بازپیاده‌سازی قابلیت‌های Faoxima روی Cloudflare

## دامنه و وضعیت

مرجع بررسی: [Mmd-Amir/Faoxima](https://github.com/Mmd-Amir/Faoxima)، کامیت `814344b017f19285574bec323d497a4612446bad`.

این پیاده‌سازی **PHP را داخل Worker اجرا نمی‌کند**. منطق جدید JavaScript، ذخیره‌سازی Durable Objects SQLite، API مشتری و مینی‌اپ خودمیزبان دارد. فایل‌های PHP، MySQL، installer و vendor پروژه مرجع داخل `public/` کپی نشده‌اند.

این نسخه انتقال یکپارچهٔ بخش بزرگی از قابلیت‌های تجاری مرجع است؛ **ادعای برابری صددرصد با تمام تنظیمات فرعی و تمام درگاه‌های قدیمی Faoxima ندارد**. جدول زیر مرز آن را مشخص می‌کند. تست شبیه‌سازی‌شده یا Workerd محلی به معنی تأیید حساب واقعی درگاه یا نسخهٔ نصب‌شدهٔ پنل شما نیست.

پشتیبانی از یک خانواده به معنی پشتیبانی همه نسخه‌های ناسازگار آن نیست. بعضی عملیات اساساً در API آن پنل وجود ندارند؛ مینی‌اپ دکمه‌های نامرتبط را نمایش نمی‌دهد و backend نیز درخواست نامعتبر را رد می‌کند.

برای x-ui، آدرس مدیریتی همیشه آدرس اتصال کاربر نیست. `publicHost` و `subscriptionBase`، tagهای inbound، service IDs و stream settings را متناسب با سرور واقعی تنظیم کنید. API سالم به‌تنهایی اثبات قابل‌اتصال‌بودن مسیر شبکهٔ VPN مشتری نیست؛ یک اتصال آزمایشی واقعی هم لازم است.

## راه‌اندازی Cloudflare

همان Worker و bindingهای v2 حفظ می‌شوند. نسخه جدید نیاز به PHP، MySQL، Docker یا cron سیستم‌عامل ندارد.

```bash
npm ci
npm run build
npx wrangler secret put VAULT_KEY
npm run deploy
```

`VAULT_KEY` باید حداقل ۳۲ کاراکتر تصادفی و محرمانه باشد. آن را در Git یا کد قرار ندهید. تغییر یا گم‌کردن این کلید بدون مهاجرت باعث خوانده‌نشدن اطلاعات اتصال و انبار رمزگذاری‌شده می‌شود. این کلید را کنار رمز فایل پشتیبان اما در محل امن جداگانه نگه دارید.

secretهای قبلی `ADMIN_PASSWORD`, `BOT_TOKEN`, `WEBHOOK_SECRET` همچنان کاربرد دارند. در پنل وب، وب‌هوک را دوباره ثبت کنید تا `pre_checkout_query` برای Stars نیز فعال شود.

در **کارگاه ربات ← سرویس / VPN ← تنظیمات**:

1. نشانی عمومی Worker را به‌صورت HTTPS ثبت کنید.
2. برند، قوانین، شماره، سقف‌ها، سهمیه تست و چت گزارش را تنظیم کنید.
3. پنل‌ها یا انبار را بسازید و «آزمایش» بزنید.
4. پلن، قفسه و قیمت‌ها را تعریف کنید.
5. روش‌های پرداخت را جداگانه اضافه کنید؛ کلیدهای درگاه در Vault ذخیره می‌شوند.
6. کاربر از `/vpn`، `/vpnservices`، `/wallet` یا `/vpnportal` استفاده می‌کند.

مینی‌اپ اصلی در `/portal/` است. خارج از تلگرام باید لینک یک‌بارمصرف صادرشده توسط ربات داشته باشد؛ واردکردن دستی user_id یا initDataUnsafe، ورود معتبر نیست. لینک ورود شخصی است و دو دقیقه اعتبار دارد؛ نشست مشتری یک ساعت اعتبار دارد.

## چند ربات در همان Worker

از نوار **ربات‌های من**:

- عنوان، توکن یک ربات متفاوت و نشانی عمومی پنل را ثبت کنید.
- getMe توکن را بررسی می‌کند؛ همان توکن دوباره یا به‌عنوان ربات اصلی ثبت نمی‌شود.
- هر ربات یک Durable Object/SQLite مجزا دارد. کیف پول، کاربران، فایل‌ها، پنل‌ها و درگاه‌ها جدا هستند.
- پس از انتخاب ربات در نوار مدیریت، APIهای مدیر در زمینه همان ربات اجرا می‌شوند. نوار بالای پنل، ربات جاری را نشان می‌دهد.
- کلیدهای مالی و اطلاعات v1 والد به ربات فرزند ارث نمی‌رسند. پنل‌ها/قیمت‌ها/درگاه‌های فرزند را جدا تنظیم کنید.
- ثبت وب‌هوک یک عمل مستقل با تأیید است. ثبت آن، وب‌هوک قبلی همان توکن را جابه‌جا می‌کند؛ pending updateها عمداً حذف نمی‌شوند.
- مسیرها مانند `/bots/<id>/portal/`, `/bots/<id>/telegram/webhook` و `/bots/<id>/sub/<token>` هستند.
- مسیرهای عمومی فرزند فقط API مشتری، پرداخت و اشتراک را عبور می‌دهند؛ ارسال header ساختگی، دسترسی مدیر ایجاد نمی‌کند.
- تغییر توکن از مدیر ربات‌ها فقط برای **همان bot ID** مجاز است؛ داده یک ربات با توکن ربات دیگر مخلوط نمی‌شود.
- ایجاد زنجیرهٔ ربات‌های فرزند تو در تو غیرفعال است. سقف فعلی ثبت ۲۰ ربات است.
- پشتیبان داده‌های هر ربات جدا گرفته می‌شود؛ پشتیبان والد، دادهٔ SQLite فرزندان را به‌صورت یک snapshot سراسری جمع نمی‌کند.

## امنیت پول و ساخت سرویس

- فقط قیمت و پیش‌فاکتور محاسبه‌شدهٔ سرور پذیرفته می‌شود.
- انتخاب پلن، نقش/تخفیف، قیمت، نام و TTL در quote ثبت می‌شود. تغییر پلن یا نقش، quote قدیمی را نامعتبر می‌کند.
- رزرو کیف پول، رزرو کانفیگ و ثبت عملیات در یک تراکنش SQLite انجام می‌شوند.
- کسر نهایی بعد از پاسخ معتبر ساخت انجام می‌شود. شکست قطعی، رزرو را آزاد می‌کند.
- تایم‌اوت به معنی «ساخته نشد» نیست؛ عملیات به review می‌رود و پول دوباره کسر نمی‌شود.
- تطبیق ساخت، فقط اسم و حجم را نمی‌سنجد: marker عملیات، UUID، public key یا شناسه مرحله تخصیص نیز بررسی می‌شود تا حساب هم‌نام دیگری تصاحب نشود.
- لغو عملیات نامشخص فقط برای مدیر و بعد از اثبات نبود کاربر/تغییر در مقصد مجاز است. مرحلهٔ نیمه‌تمام IBSng نیازمند بررسی شناسه تخصیص‌یافته است.
- انتقال و استرداد نیازمند تأیید مدیرند. استرداد به **کیف پول داخلی پرداخت‌کننده** است، نه برگشت خودکار پول به بانک/رمزارز/Stars.
- در استرداد انباری، مدیر باید غیرفعال‌سازی واقعی کانفیگ را خارج از پنل انجام داده و صریحاً تأیید کند.
- اشتراک، QR و کانفیگ نیازمند مالکیت و عبور از قفل عضویت‌اند. لینک اشتراک bearer secret است؛ هرکس آن را داشته باشد ممکن است از آن استفاده کند، پس نباید منتشر شود.

هیچ API بیرونی تراکنش مشترکی با SQLite ندارد. در قطع ارتباط، تغییر دستی سرور، restore تاریخی یا خطای خود ارائه‌دهنده، بررسی انسانی ممکن است لازم باشد. ضمانت exactly-once شبکه یا بدون‌قطعی ارائه نمی‌شود.

## پرداخت‌ها

### کارت‌به‌کارت

رسید JPEG/PNG/PDF فقط وارد صف بررسی می‌شود. مدیر واریز واقعی را بررسی می‌کند؛ عکس، متن کاربر یا OCR سند بانکی قطعی نیست. گزینه‌ای که بدون استعلام یا بررسی واقعی هر فیش را خودکار معتبر کند، اضافه نشده است.

### زرین‌پال، آقای پرداخت و زرین‌پی

ساخت فاکتور و verify سمت سرور پیاده‌سازی شده‌اند. مبلغ از فاکتور ذخیره‌شده گرفته می‌شود، نه query کاربر. تومان/ریال طبق قرارداد هر سرویس اعمال می‌شود. Authority/transaction ID و مرجع مصرف‌شده کنترل می‌شوند.

### NOWPayments و Plisio

- برای NOWPayments، API key و IPN secret لازم است. HMAC webhook بررسی و سپس وضعیت از API ارائه‌دهنده دوباره خوانده می‌شود.
- invoice ID، order ID، قیمت/ارز و وضعیت نهایی کنترل می‌شوند؛ confirmed موقت به‌جای finished پذیرفته نمی‌شود.
- Plisio در این نسخه صورتحساب مبتنی بر USD با تسویه TRX می‌سازد و operation واقعی را با شناسه و مبلغ بررسی می‌کند.
- **نرخ USD/IRT توسط مدیر تنظیم می‌شود**؛ نرخ بازار زنده به‌طور خودکار دریافت نمی‌شود. حداقل مبلغ و کارمزدهای ارائه‌دهنده همچنان باید رعایت شوند.

### Telegram Stars

createInvoiceLink، pre-checkout و successful_payment پیاده‌سازی شده‌اند. pre-checkout مسیر سریع جدا دارد تا پشت عملیات کند پنل VPN نماند. مبلغ XTR، پرداخت‌کننده و payload بررسی می‌شوند. callback سمت مرورگر به‌تنهایی موجودی را زیاد نمی‌کند.

قبل از فروش کالای دیجیتال، مقررات جاری Telegram Stars و ارائه‌دهنده پرداخت را بررسی کنید. بازپرداخت خودکار Stars به منبع اولیه در این نسخه اضافه نشده است.

### TRX، TON، USDT-TRC20 و USDT-TON

- مقدار با واحد صحیح کوچک‌ترین واحد محاسبه می‌شود؛ محاسبه مالی متکی به اعشار شناور نیست.
- شبکه، مقصد، قرارداد رسمی توکن، موفقیت تراکنش، زمان، تأییدها و هش مصرف‌نشده بررسی می‌شوند.
- **Memo اختصاصی فاکتور برای هر دو شبکه الزامی است.** پذیرش هش عمومی فقط بر اساس مقصد/مبلغ، راه امنی برای انتساب واریز به خریدار نیست.
- در TRON، memo از `raw_data.data` بررسی می‌شود؛ در TON از پیام تراکنش.
- کیف پول یا صرافیِ بدون امکان ارسال memo با این مسیر تأیید خودکار سازگار نیست؛ از درگاه پرداخت میزبان یا بررسی پشتیبانی استفاده شود.
- بعد از پایان مهلت، واریز جدید انجام نشود. هش تراکنشِ انجام‌شده در بازه صحیح همچنان قابل بررسی است؛ زمان واریز باید متعلق به همان فاکتور باشد.
- عبارت بازیابی و کلید خصوصی لازم نیست و نباید وارد پنل شود. فقط آدرس دریافت و API key استعلام، در صورت نیاز، استفاده می‌شود.

## مواردی که هنوز معادل کامل ندارند

این موارد **عمداً به‌عنوان قابلیت فعال یا تأییدشده نمایش داده نشده‌اند**:

- اتصال اختصاصی IRanpay 1/2/3، Swap/TetraPay، Perfect Money، FloyPay و gatewayهای قدیمی‌تر با قراردادهای متفاوت؛
- دریافت خودکار نرخ لحظه‌ای تومان/رمزارز از منبع بازار؛
- برگشت خودکار وجه به منبع اولیه برای تمام درگاه‌ها؛
- تمام جزئیات ریز نقش‌ها، تاس تلگرام، بعضی محدودیت‌ها و گردش‌های جانبی نسخه PHP؛
- واردکردن مستقیم dump دیتابیس MySQL فاکسیما و بازاجرای SQL خام؛
- دستورهای shell، نصب Ubuntu، mysqldump یا تعویض فایل‌های PHP؛ معادل این عملیات در این معماری deploy، Cron/Alarm و backup ساختاریافته است؛
- تضمین کارکرد تمام forkها/نسخه‌های غیراستاندارد پنل‌ها، مسیرهای خصوصی یا گواهی نامعتبر.

این فهرست نباید با قابلیت‌هایی که پیاده‌سازی شده‌اند ولی هنوز **به حساب واقعی شما متصل نشده‌اند** اشتباه شود.

## آزمون‌ها

```bash
npm test
npm run smoke
npm run build
npx wrangler deploy --dry-run
```

آزمون مرورگر فقط روی محیط محلی جدا:

```bash
# .dev.vars محلی (نه production):
# ALLOW_DEFAULT_PASSWORD=true
# BOT_TOKEN=123:TEST_TOKEN
# WEBHOOK_SECRET=<local-secret>
# VAULT_KEY=<local-test-key-at-least-32-characters>

npm run dev
# ترمینال دیگر:
npx playwright install --with-deps chromium
npm run test:ui
npm run test:services-ui
```

آزمون خدمات داده مالی و کانفیگ **نمونه** می‌سازد و باید فقط روی فضای محلی آزمایشی اجرا شود. در تست‌ها از سرویس VPN واقعی یا حساب مالی واقعی استفاده نشده است. تست مرورگر خدمات، ثبت پلن/انبار، ورود مشتری، quote، رزرو و کسر واقعی SQLite محلی، دریافت کانفیگ و لینک اشتراک را اجرا می‌کند. آزمون providerها قرارداد HTTP را شبیه‌سازی می‌کند.

برای پذیرش عملیاتی در حساب شما، پس از تنظیم secretها و آدرس‌های واقعی: یک پلن آزمایشی کم‌حجم، ساخت/اتصال واقعی، تمدید، پایان سهمیه، قطع ارتباط، webhook تکراری، پرداخت موفق/ناموفق و بازگردانی پشتیبان جداگانه بررسی شوند.
